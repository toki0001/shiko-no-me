# 編集パネルの固定領域の回帰確認

## 2026-09-20の原因と対策

旧パネルは外側に32px（狭幅28/20px）のpaddingを持ち、その内側の見出しをsticky化していた。PCではtop:0、モバイルではtop:-20pxと異なる補正が別のCSSファイルに分散していた。外側自体がoverflow:autoだったため、見出しの配置と本文スクロールが余白に依存した。公開画面でパネル上端123.65px、見出し上端155.63px（差31.99px）を実測。

修正は外枠をpadding:0・overflow:hiddenの縦flexへ。先頭の見出しを縮まない兄弟要素にし、本文だけをmin-height:0・overflow:autoへ。パネルの配置規則をboard.cssに集約し、stickyと負のtop補正を撤去。カード変更時の先頭復帰先も本文へ変更。

## ブラウザ検証（UI変更時の必須ゲート）

Browserスキルでローカル確認サーバーを開き、テスト用ノートのカード編集を開く。アプリの内容やDOMをevaluateで書き換えず、実操作で用意する。

Node REPLで次のモジュールを絶対パスからimportし、Browserスキルのtabを渡す。

```js
const checks = await import('file:///ABSOLUTE_PROJECT_PATH/scripts/check-inspector-layout.mjs');
await checks.checkInspectorLayout(tab);
```

ヘッダー上端=パネル内側上端（誤差1px以内）、本文はその直下、外枠はスクロールしない、×は44px相当で遮蔽なし、横はみ出しなしを検証。実際のホイールで本文の末尾と先頭へ移動し、同じ条件を再確認する。旧版には最初の位置チェックで失敗する。

- 通常PC、1150px付近、941/940px付近、768px、390px、低い横画面で行う。報告には実測viewportと実際に適用された表示モードを使う。端数やブラウザ倍率で境界からずれる場合は境界の両側も確認。
- 線の色と枝の整理を開き、長い本文・タイトルでスクロールさせる。
- 一番下で×を押して閉じ、再度開く。別カードを選ぶと本文が先頭に戻り、ヘッダー位置は不変であることを確認。
- PC/スマホ幅でスクロール途中または末尾の画像を確認する。仮想画面サイズは終了時にresetする。
- npm testは別途実行。上記のブラウザ検証を単体テスト成功で代用しない。

固定要素の再発確認は他プロジェクトでも、祖先のoverflow/padding/transform、画面幅別のCSS上書き、本文が増えた状態の実測をセットにする。CoHoursの過去の浮き報告はowner-rules.mdの2026-08-10 G2に記録があるが、同じCSS原因と判定したものではない。
